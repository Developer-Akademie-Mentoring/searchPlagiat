SearchPlagiat

GitHub-Repository-URL eingeben und auf Plagiate prüfen

Die App lädt den Quellcode des Repos über die GitHub API herunter und durchsucht anschließend GitHub nach ähnlichem Code. Beides erfordert einen Token – ohne ihn werden die meisten Anfragen abgelehnt.

So erstellst du einen:

  1. GitHub → Settings → Developer settings
  2. Personal access tokens → Tokens (classic)
  3. „Generate new token (classic)" klicken
  4. Keine Berechtigungen nötig – direkt generieren

Beispiel:

ghp_abc123XYZ456def789ghi0JKL

SearchPlagiat lädt den Quellcode eines GitHub-Repos herunter, sucht nach auffälligen Funktionsnamen (lang, individuell, human-like) und gleicht diese mit öffentlichen Repositories auf GitHub ab. Übereinstimmungen bei solchen Namen sind ein starkes Plagiat-Signal.

Wie funktioniert SearchPlagiat?

  1. Repo-Analyse. Es werden bis zu 15 Code-Dateien aus dem angegebenen Repository geladen. Darin werden Funktionsnamen gesucht, die „menschlich" wirken – also individuell und nicht generisch (z.B. calculateShippingCost statt get oder data). Die 15 auffälligsten Funktionen werden vorgeschlagen.
  2. Auswahl. Du siehst diese Vorschläge als Checkboxen und kannst einzelne abwählen, die nicht durchsucht werden sollen. Zusätzlich kannst du eigene Funktionsnamen manuell ergänzen – diese werden bei der Suche zuerst geprüft. Tipp: Je weniger Funktionen gesucht werden, desto unwahrscheinlicher findet man ein Ergebnis – suche lieber nach vielen Funktionen.
  3. GitHub-Suche. Für jeden bestätigten Namen wird über GitHubs Code-Search-API nach anderen öffentlichen Repositories gesucht, die exakt diesen Namen enthalten. Wegen eines sehr strengen API-Limits liegt zwischen den Anfragen eine kurze Pause; wird das Limit trotzdem erreicht, pausiert die Suche automatisch und du kannst nach einer Wartezeit fortsetzen.
  4. Ergebnisse. Gefundene Repositories werden nach Anzahl der Übereinstimmungen sortiert. Jede Ergebnis-Karte zeigt die übereinstimmenden Funktionen (mit aufklappbarem Code-Vergleich: dein Code neben dem Code aus dem gefundenen Repo), sowie geprüfte, aber nicht gefundene Namen in einem einklappbaren Bereich – auch dort lässt sich der Code aufklappen und bei Bedarf gezielt im gesamten Repo nachsuchen.
  5. Detail Check. GitHubs Suche hat Grenzen: sie schließt Forks aus, liefert pro Suchbegriff nur die ersten 10 Treffer und indexiert keine Dateien über 384 KB. Deshalb kannst du pro Repo einen „Detail Check" auslösen – dabei wird der tatsächliche Code dieses einen Repos komplett direkt geladen (alle Code-Dateien) und lokal geprüft, ob die noch offenen Namen dort vorkommen, unabhängig von GitHubs Such-Index.

Wichtig: Die automatische Erkennung ist ein Kandidaten-Filter, kein Beweis. „Kein Treffer" bedeutet nicht zwangsläufig, dass der Code nirgendwo existiert. Der Code-Vergleich in den Ergebnissen dient dazu, dass du dir selbst ein abschließendes Bild machen kannst.
